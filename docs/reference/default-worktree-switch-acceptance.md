# Default-worktree switch — 요구사항과 수용 기준

이 문서는 **기본 워크트리 전환(Make Default Worktree)** 기능에 대해 사용자가 제시한 요구사항과,
각 항목의 검증 상태·근거를 기록한다. 새 변경을 넣기 전에 여기 적힌 항목이 여전히 성립하는지 확인한다.

관련 문서: [`local-mac-build-asar-integrity.md`](./local-mac-build-asar-integrity.md) ·
포크 변경 이력은 [`../../FORK_CHANGELOG.md`](../../FORK_CHANGELOG.md)

---

## 스왑 한 번에 대한 계약

이 표가 이 기능의 계약이다. 아래 항목이 하나라도 어긋나면 결함이다.
"관측된 실패"는 실제로 발생했던 사례이며, 각 항목에 회귀 테스트가 걸려 있다.

### 반드시 일어나야 하는 일

| # | 반드시 | 확인 방법 |
|---|---|---|
| M1 | 두 워크트리의 브랜치가 제자리에서 맞바뀐다 | `git branch --show-current` 양쪽 |
| M2 | 각 워크트리의 **탭 집합이 통째로 반대편으로 이동**한다 | 영속 `tabsByWorktree` 개수·구성이 좌우 교환 |
| M3 | 분할 탭의 **팬 트리와 leaf id가 그대로** 유지된다 | 탭별 팬 수 배열이 좌우 교환 |
| M4 | 각 에이전트가 **같은 팬(`tabId:leafId`)에서 같은 provider 세션**으로 재개된다 | 전환 **이후** 도착한 훅의 세션 id 대조 |
| M5 | 재개된 에이전트가 **사이드바에서 에이전트 행**으로 보인다 | `worktree ps`의 `agents[]` 개수 |
| M6 | 열린 에디터/파일 탭이 브랜치를 따라 교환된다 | `unifiedTabs`의 editor 항목 |
| M7 | 커밋 안 된 변경이 자기 브랜치를 따라간다 | 파일 내용 확인 |
| M8 | 플레인 셸 탭은 **탭·위치·분할 위치를 유지한 채** 새 셸로 재기동된다 | 탭 생존 + PTY 재획득 |

### 절대 일어나선 안 되는 일

| # | 금지 | 관측된 실패 | 감시 신호 |
|---|---|---|---|
| N1 | **탭이 사라진다** | 단일 팬 플레인 탭이 스왑마다 삭제됨 | `tab_close {reason:"pty-exit"}` 브레드크럼이 찍히면 결함 |
| N2 | **탭이 늘어난다(포크)** | 클로드 1·코덱스 1이 각각 3개로 복제, 4탭 → 7탭 | 양쪽 탭 합계가 변하면 결함 |
| N3 | **분할 팬이 줄어든다** | 3팬 탭이 1팬으로 붕괴 후 미복구 | 탭별 팬 수 불일치 |
| N4 | **에이전트가 맨 셸로 강등된다** | 코덱스 팬이 셸 프롬프트로 복귀 | 팬 프리뷰가 셸 프롬프트 |
| N5 | **에이전트가 사이드바에서 터미널 행으로 강등된다** | `launchAgent`는 살아있는데 상태 행이 없어 회색 터미널로 표시 | `agents[]` 개수 < 에이전트 수 |
| N6 | **에이전트가 새 탭으로 포크된다** | 보존 탭은 셸이 되고 옆에 새 탭이 생김 | N2와 동일 신호 |
| N7 | **재개가 실패해 팬이 죽는다** | 트랜스크립트 없는 세션으로 `--resume` → 즉시 종료 | 팬에 resume 명령 직후 셸 프롬프트 |
| N8 | **전환이 영구히 거부된다** | 재시작 후 훅 없는 에이전트 때문에 계속 거부 | `mode_b_not_ready` 반복 |
| N9 | **Claude 대화 기록이 유실된다** | 한글 경로 충돌 시 폴더가 임시 이름으로 방치 | `.orca-transcript-swap-*` 잔해 |

### 허용되는 일 (결함 아님)

- **지연**: 팬이 몇 초 뒤에 살아나는 것. 사후 재기동 스윕이 최대 75초까지 재시도한다.
- **플레인 셸의 스크롤백 유실**: 셸 프로세스는 옮길 수 없다. 탭·위치·분할은 유지된다.
- **한 번도 대화하지 않은 에이전트가 새 세션으로 시작**: 보존할 세션 자체가 없다.
  이 경우 팝업이 해당 탭 이름을 경고로 알린다.
- **무시된 파일이 제자리에 남는 것**: 의도된 동작.

## R1. 전환 후 상태가 전부 보존될 것

> "사이드바, 터미널상태, 위치, 분할터미널 전부 상태 유지하도록"

**대상**: 터미널 탭 집합·순서·활성 탭, 탭 안의 분할 팬 트리(leaf id 포함), 에디터/파일 탭.

| 항목 | 기준 |
|---|---|
| 탭 | 어떤 탭도 삭제되지 않는다. 단일 팬 탭도 포함 |
| 팬 | 분할 트리의 모든 leaf가 살아남고 각자 PTY를 되찾는다 |
| 위치 | 탭 순서와 활성 탭이 유지된다 |
| 에디터 | 열린 파일 탭이 브랜치를 따라 반대편으로 교환된다 |

**허용**: 지연은 무방하다("딜레이있어도됨"). 플레인 셸의 스크롤백은 프로세스를 옮길 수 없으므로 유실된다.

**검증**: 실기 반복 스왑에서 탭·팬 수, 영속 레이아웃, 에디터 탭이 모두 좌우로 교환됨을 확인.
회귀 감시는 `pane_exit_teardown` / `tab_close` breadcrumb 부재로 확인한다 —
결함이 있을 때는 스왑마다 `tab_close {reason: "pty-exit"}` 이 찍혔다.

## R2. 에이전트 세션이 같은 세션으로 복구될 것

> "클로드랑 코덱스 세션이 제대로 복구되는지 테스트해. 똑같은 테스트도 두번이상하고"

**기준**: 전환 후 각 에이전트 팬이 **같은 `paneKey`(tabId:leafId)** 에서 **같은 provider 세션 id**로 재개된다.
새 탭으로 포크되면 실패로 간주한다. 클로드·코덱스 둘 다.

**검증 방법 (중요)**: `last-status.json`을 전후 비교하는 것만으로는 **불충분하다** —
그 파일은 오래된 항목을 남기므로 에이전트가 죽어도 통과한다.
반드시 **전환 이후에 도착한 훅**(`receivedAt > 전환 시각`)만 인정하고,
보고 주체의 `worktreeId`가 이동한 쪽인지 함께 본다.

## R3. 분할 팬 안의 에이전트도 동일하게 동작할 것

> "분할터미널도 에이전트들어가있어도 잘 되지?"

**기준**: 한 탭이 `claude | codex | 플레인 셸` 3분할일 때, 두 에이전트 팬이 각자 자기 세션으로 돌아오고
3팬 구조가 그대로 유지된다.

## R4. 사이드바가 에이전트를 에이전트로 인식할 것

> "여전히 사이드바에 3번쨰 클로드가 터미널로 뜨고, 스플릿된거까지 보면 5개 떠야하는데 4개만뜸"
> "사이드바에서 ai에이전트들을 제대로 인식하고, 각 터미널도 제대로 되는거 맞지?"

**기준**: 전환 후에도 에이전트 탭이 사이드바에서 프로바이더로 표시된다(플레인 터미널로 강등되지 않는다).

**판정 근거**: 사이드바의 프로바이더 아이콘은 `tab.launchAgent`에서 나온다.
`orca worktree ps`의 `agents[]`는 **훅이 도착해야 채워지므로** 판정 기준으로 쓰면 안 된다
(전환을 한 번도 안 한 새 에이전트도 비어 있다). 팬 제목의 `✳` 글리프도
커스텀 제목을 준 탭에서는 나타나지 않으므로 기준이 될 수 없다.

## R5. 미추적 파일 이동 여부를 선택할 수 있을 것

> "깃 미추적 파일은 같이 안넘어간다는 내용도 팝업에 포함시켜" → 실측 후 **옵션화**로 확정

**실측**: 미추적 파일은 기본적으로 **브랜치를 따라 이동한다**
(`git stash push --include-untracked`). 전환 팝업의 기존 문구는 이를 명시하지 않았다.

**결정**: 동작을 강제로 바꾸지 않고 **팝업 체크박스로 선택**하게 한다.

| 설정 | 동작 |
|---|---|
| 기본(꺼짐) | 미추적 파일이 브랜치를 따라 이동 |
| "추적되지 않은 파일은 제자리에 두기" | 폴더에 그대로 남고 브랜치만 교체 |

CLI: `orca worktree default set --keep-untracked-in-place`.
RPC `includeUntracked`는 **선택적 필드**이며 생략 시 기존 동작을 유지한다(구버전 클라이언트 호환).
무시된 파일은 두 경우 모두 제자리에 남는다.

## R6. 한글 워크트리에서도 안전할 것

> "워크트리가 한글인경우는 메인전환 막아야하는거아님? 괜찮나"

**결론**: **막을 필요 없다.** 경로·브랜치·파일명이 모두 한글인 실제 git 저장소로 스왑을 검증했고,
미추적 한글 파일까지 정상 이동한다. `git worktree list --porcelain`은 한글 경로를 인용부호 없이
출력하고, 경로 비교는 이미 `NFC` 정규화를 거친다(macOS NFD 대응).

**단, 별개의 지뢰가 있었다**: Claude는 트랜스크립트 폴더명을 `[^a-zA-Z0-9]` → `-` 로 접는다.
따라서 같은 부모 아래 **글자 수가 같은 한글 워크트리 둘**은 폴더가 충돌한다.

```
/repo/workspaces/작업트리  ->  -repo-workspaces-----
/repo/workspaces/한글경로  ->  -repo-workspaces-----   ← 동일
```

이 상태에서 트랜스크립트 교환이 돌면 유일한 폴더를 임시 이름으로 치운 뒤 실패하여 **대화 기록이 유실된다**.
→ 인코딩이 같으면 교환을 건너뛰고, 3단계 rename 중 실패 시 원위치로 되돌린다.

## R7. 모든 경우의 수에서 성립할 것 (총괄 목표)

> "모든 경우의수에서 사이드뷰와 내부 탭(멀티터미널, 파일뷰 등등)이 정상적으로 교환되도록하기. 딜레이있어도됨"

R1~R4를 **단일 팬 / 다중 팬 / 에이전트 / 플레인 셸 / 에디터 탭**의 조합에 대해 만족해야 한다.
지연은 허용되므로, 경합에서 밀린 팬은 사후 스윕으로 복구하는 방식이 정당하다.

## R8. 로컬 빌드에서 권한 팝업이 반복되지 않을 것

> "왜 오르카 매번 파일 허용 눌러줘야함?"

**원인**: 로컬 빌드는 애드혹 서명이라 코드 신원이 없고, 지정 요구사항이 **그 빌드의 cdhash 자체**가 된다.
빌드마다 해시가 바뀌므로 macOS TCC는 매번 다른 앱으로 보고 권한을 초기화한다.
(upstream도 [`config/electron-builder.config.cjs`](../../config/electron-builder.config.cjs)에 같은 현상을 기록해 두었다.)

**해결**: 로그인 키체인에 자체 서명 **코드 서명** 인증서(`Orca Local Signing`)를 만들어 신뢰시키면,
지정 요구사항이 인증서 기준으로 바뀌어 재빌드해도 동일해진다.

```
전 (애드혹)   cdhash H"61d26bf4…" / cdhash H"878379ee…"        서로 다른 빌드 = 다른 앱
후 (인증서)   identifier "com.stablyai.orca" and certificate leaf = H"50560dd4…"   동일
```

`config/scripts/sign-local-mac-app.cjs`가 이 인증서를 자동으로 찾아 쓰고,
없으면 애드혹으로 폴백하므로 다른 머신의 빌드도 깨지지 않는다.
인증서 이름을 바꿨다면 `ORCA_LOCAL_SIGN_IDENTITY`로 지정한다.

## 작업 규칙 (사용자 지시)

- **브랜치 추가/삭제, 푸시(PR 생성 포함)는 직전 지시에 명시적으로 포함된 경우에만** 수행한다.
  같은 세션의 앞선 승인은 다음 건에 적용되지 않는다.
- 검증 결과는 실증으로 뒷받침한다. 추측으로 고치지 말고, 계측을 심어 범인을 특정한 뒤 고친다.
- `build:mac` 실행 중에는 리포에 아무것도 쓰지 않는다(asar 오프셋 손상).

## 검증에서 반복적으로 틀렸던 잣대 (재사용 금지)

이 기능은 헤드리스 판정이 까다롭다. 아래는 실제로 **잘못된 결론을 내게 만든** 측정들이다.

| 잣대 | 왜 틀렸나 |
|---|---|
| `last-status.json` 전후 비교 | 오래된 항목이 남아 죽은 에이전트도 "유지"로 통과 |
| `orca worktree ps`의 `agents[]` | 훅 도착 전에는 비어 있음 — 새 에이전트도 0으로 나옴 |
| 팬 제목의 `✳` 글리프 | 커스텀 제목을 준 탭에서는 표시되지 않음 |
| 영속 `orca-data.json` 즉시 조회 | 스왑 직후 한 세대 지연 — 있는 탭이 없는 것처럼 보임 |
| `terminal list`의 라이브 팬 수 | 마운트되지 않은 워크트리의 탭은 아예 안 보임 (활성화 필요) |

**신뢰할 수 있는 절차**: 에이전트를 먼저 프롬프트해 세션을 갖게 한다 → 전환 →
목적지 워크트리를 활성화해 팬을 마운트시킨다 → **전환 이후 타임스탬프의 훅만** 인정해 세션을 대조한다.

## R9. 적대적 리뷰에서 나온 취약점이 닫혀 있을 것

Codex + 서브에이전트 적대적 리뷰(2026-08-09)가 17건을 보고했고, 코드로 재확인한 뒤 아래를 고쳤다.
각 항목은 회귀 테스트로 고정되어 있다.

| # | 취약점 | 조치 |
| --- | --- | --- |
| 데이터 파괴 | `stash drop stash@{0}`이 위치 기반이라, 동시에 들어온 **사용자 자신의 stash**를 지울 수 있었다 | 우리 항목을 SHA로 식별해 drop하고, 함께 사라진 다른 항목은 `stash store`로 되돌린다 |
| 데이터 파괴 | park 브랜치를 `-D`로 무조건 삭제 — 스왑 중 훅이 그 브랜치에 커밋하면 그 커밋이 사라진다 | 파킹 **직전** 커밋을 기준으로, 브랜치가 움직였으면 삭제하지 않고 남긴다 |
| 복구 불가 | 롤백이 성공해도 rescue ref를 지우지 않아 재시도마다 숨은 ref가 쌓였고, 반대로 캡처 실패 경로는 ref 이름을 알리지 않고 던졌다 | 복원 성공 시 ref 회수, 복원 실패 시 ref 경로를 담은 `recovery_required` 오류 |
| 데이터 파괴 | 트랜스크립트 3단계 rename 중 3번째가 실패하면 롤백이 무효(대상 디렉터리가 이미 점유됨) — 왼쪽 히스토리가 `.orca-transcript-swap-*`에 고립 | 커밋된 단계를 역순으로 되돌린다. 그래도 실패하면 스테이징 경로를 오류에 담는다 |
| 데이터 유출 | POSIX 경로의 백슬래시가 다른 프로젝트의 트랜스크립트 키와 별칭이 될 수 있었다 | 해당 경로는 스왑을 거부(`claude_transcript_swap_ambiguous_path`) |
| 상태 오염 | opaque worktree id를 `.trim()` — 끝에 공백이 있는 경로는 **다른 워크트리**의 id가 된다 | id는 그대로 전달, 이미 `id:` 접두가 붙은 selector만 정규화 |
| 신뢰 경계 | `followAgents`가 sleep/wake 없이 원격 호출 가능 — PTY는 옛 폴더에 남고 탭·히스토리만 반대편으로 표시된다 | `uiFlow` 없는 follow는 거부. CLI도 `--follow-agents`에 `--ui-flow`를 요구 |
| 신뢰 경계 | 불린 검증이 fail-open — `includeUntracked:"false"`가 조용히 "이동함"으로 해석 | 파괴적 파라미터는 엄격 불린으로 검증 |
| 경합 | readiness를 await한 뒤에야 in-flight를 세팅해서, 동시에 시작한 두 전환이 모두 통과하고 두 번째가 첫 번째의 wake 스냅샷을 덮어썼다 | await 이후 **같은 동기 턴**에서 재확인 후 점유 |
| 경합 | wake 하나가 모든 워크트리의 sleep guard를 전역 해제했고, sweep 취소도 전역이라 다른 리포의 복구를 끊었다 | 둘 다 워크트리 단위로 범위화 |
| 라이브니스 | 90초 teardown 창이 sweep(최대 75초)보다 오래 살아, 그 사이의 **진짜** 종료가 삼켜지고 탭이 죽은 채 남았다 | 마지막 sweep이 끝나면 teardown 소유권을 반납 |
| 라이브니스 | 멈춘 git 훅이 양쪽을 재운 채로 전체를 무기한 잠갔다(로컬 IPC는 caller timeout을 무시) | 전환용 git 호출에 5분 데드라인 |
| 라이브니스 | follow wake가 저장된 탭 **전부**를 한 렌더 패스에 마운트 — 탭이 많으면 렌더러가 수십 초 멈춘다 | 에이전트 탭 우선, 6개씩 300ms 간격 배치 마운트 (누락분은 sweep이 회수) |
| 복구 | 한쪽 sleep이 실패하면 스왑을 거부하면서, **성공적으로 잠든 반대쪽**은 깨우지 않고 방치했다 | 거부 경로에서 잠든 쪽을 깨운다 |

### 고치지 않고 남긴 것 (근거와 함께)

- **무시(ignored) 파일 덮어쓰기**: `git switch`는 추적 파일이 ignored 파일을 덮어쓰는 것을 허용한다. 이건 git 자체 동작이고 stash/rescue로 복구되지 않는다. 계약상 "ignored 파일은 제자리"라는 문구는 *Orca가 옮기지 않는다*는 뜻이며, git이 덮어쓸 수 있다는 점은 여기 명시해 둔다.
- **재시도 비멱등성**: 응답이 유실된 뒤 동일 요청을 재시도하면 "이 두 경로의 브랜치를 교환"이므로 원위치로 되돌아간다. mutation id가 없어 중복 제거를 못한다. 자동화에서 재시도할 때는 `worktree list`로 현재 상태를 먼저 확인해야 한다.
- **크래시 원자성**: git 성공 후 · 상태 영속화 전에 프로세스가 죽으면 브랜치는 바뀐 채 세션 소유권만 과거로 남는다. 저널이나 시작 시 정합성 검사가 없다. 정상 입력으로는 재현 트리거를 만들지 못했다.

## R10. 실측 매트릭스로 확인된 결함과 수정 (2026-08-10)

계약을 기계 판정하는 검증기로 실제 앱에서 스왑을 반복해, 아래 7건을 확정하고 고쳤다.
전부 **무성(無聲)** 부류다 — 오류도 로그도 남기지 않아 스냅샷 대조 없이는 보이지 않는다.

| # | 결함 | 증상 |
|---|---|---|
| 1 | parked PTY 사이드카가 억제 필터를 거치지 않음 | 스왑의 sleep 킬을 진짜 종료로 오인 → 배경 분할 붕괴(N3), 마지막 팬이면 탭 삭제(N1) |
| 2 | 유휴 코덱스 사이드바 강등 | 제목이 cwd뿐이면 에이전트 행 미생성 → 터미널 행(N5) |
| 3 | 클로드 작업 제목 강등 | `✳ ...` 제목이 "claude" 단어를 안 담으면 거부 → 3팬 전부-클로드 탭 포함 3개(N5) |
| 4 | shutdown 레이아웃 캡처 축소 | 반쯤 마운트된 PaneManager로 트리 재직렬화 → 분할 영구 축소(N3) |
| 5 | `persistLayoutSnapshot` 축소 | 리마운트 중 같은 패턴. 전환 창 안에서만 기존 트리를 유지하도록 제한 |
| 6 | 재키잉 충돌이 목적지 파괴 | main·렌더러 양쪽 무가드 대입 → 점유된 id로 재키잉 시 그쪽 탭 소실 |
| 7 | **sleep 킬이 영속 탭을 은퇴시킴** | `onPtyExit`가 모든 종료를 영구 종료로 처리 → 탭이 디스크에서 삭제되고 topology fence가 올라가, 이후 렌더러의 올바른 목록이 디스크 목록으로 rebase되어 **영구 고착**(N1) |

7번이 오래 못 잡던 그 사고의 근본 원인이다. 렌더러 스토어에는 탭이 멀쩡히 있는데 디스크에서만
사라지므로 렌더러 쪽 감시로는 잡히지 않았다. 수정은 렌더러가 이미 보내던 의도를 존중하는 것이다 —
sleep은 `pty.kill(id, { keepHistory: true })`로 죽이며, 그건 "이 탭은 돌아온다"는 뜻이다.

### 검증 방법

리포 경로와 상대 워크트리를 바꿔가며 3개 시나리오를 반복하고, 매 회 13개 항목을 판정한다.

- **A** 양쪽 다 에이전트: 다중 탭 + 2·3팬 분할 + **3팬 전부 클로드** + 코덱스 혼합 분할
- **B** 한쪽만 에이전트: 목적지 에이전트 0개 + 한글 경로
- **C** 비대칭: 에이전트 1 + 셸 1

M5/N5는 CLI로 읽을 수 없으므로, 실행 중인 앱의 실제 상태(탭·팬·PTY·제목)를 덤프해
**실제 사이드바 빌더**에 상태 맵을 비운 채(최악의 경우) 먹여 판정한다.

최종 결과: **A 3/3, B 3/3, C 4/4** — 전 항목 통과.

### 검증에서 반복적으로 틀렸던 잣대 (추가)

- 브레드크럼 시각을 `HH:MM:SS` 문자열로 비교 → 자정을 넘기면 전날 이벤트까지 포함된다. epoch로 비교할 것.
- 무성 삭제 감시를 리포로 한정하지 않으면 **다른 프로젝트**의 정상 정리가 실패로 잡힌다.
- 렌더러 감지기를 "탭 개수 감소"로 판정하면, 스왑처럼 목록을 통째로 다시 쓰는 경우
  하나가 빠지고 하나가 들어와 **개수가 같아 통과**한다. 집합으로 비교할 것.
- 세션 기록이 한 번도 없는 에이전트 탭이 셸로 돌아오는 것은 **스왑 결함이 아니다**.
  스왑 없이 앱 재시작만 해도 동일하게 재현된다.
